# 实验三：无人机中继收益验证

## 实验目标

验证在**卫星接入盲区/遮挡场景**下，引入 UAV 作为空中中继节点能够显著提升业务连续性，核心命题：

> **当部分无人机失去直连卫星能力时，协同中继比“无中继”或“被动中继”更稳定、更高效。**

本实验延续实验 1、2 的组织方式，但关注点从“缓存收益”和“动态拓扑稳定性”切换为**UAV 作为中继节点的接入补盲能力**。

---

## 实验设计

### 基础拓扑

使用真实轨迹构建 4SAT + 5UAV + 1GS 三层网络：

| 参数 | 值 |
|------|-----|
| 卫星轨迹 | `traces/sat_trace_4/` |
| UAV 轨迹 | `traces/uav_trace/uav_trace_full_5uav.csv` |
| 时间步数 | 200 步 |
| 中心服务器 | `GS_01` |
| SAT-UAV / SAT-GS 带宽 | 20 Mbps |
| SAT-SAT 带宽 | 100 Mbps |
| UAV-UAV 中继带宽 | 12 Mbps |
| UAV-UAV 最大中继距离 | 2.5 km |

### 盲区/遮挡注入

为了让“无人机中继”成为必要能力，本实验在真实轨迹上叠加**可预测卫星盲区窗口**：

- `UAV_01`: `[70,115)`, `[160,195)`
- `UAV_02`: `[20,75)`, `[120,170)`
- `UAV_03`: `[15,95)`, `[110,165)`
- `UAV_04`: `[40,130)`
- `UAV_05`: `[25,70)`, `[85,155)`, `[165,200)`

在盲区窗口内，该 UAV 的所有 `UAV-SAT` 链路被切断；在进入盲区前的 3 步过渡窗口内，卫星接入时延会被放大，模拟遮挡逼近和链路质量恶化。

### 业务模型

- 每个时间步，5 个 UAV 各向 `GS_01` 发起 1 条持续业务流
- 业务负载大小：1 MB
- 若该步发送失败，则视为业务超时并记入 `1200 ms` 超时惩罚

因此，本实验的“业务完成时延”不是单纯的物理传播时延，而是：

$$
T_{service} = T_{propagation} + T_{transmission} + T_{relay\ overhead} + T_{queue}\, ,
$$

若失败，则记为：

$$
T_{fail} = 1200\ ms
$$

这使得“是否能在盲区期间持续交付”会直接影响平均业务时延。

## 对比算法

### Baseline 1：无中继直连

- 仅允许 `UAV -> SAT -> ... -> GS` 直连路由
- 一旦 UAV 落入卫星盲区，则该业务直接失败
- 不使用任何 UAV-UAV 中继链路

特点：

- 实现最简单
- 对盲区极其敏感
- 恢复只能等到卫星重新可见

### Baseline 2：被动单跳中继

- 当直连失败后，等待 1 步再尝试寻找中继 UAV
- 只选择**单跳最近**的可用中继 UAV
- 不考虑中继能量、未来盲区风险和负载均衡

特点：

- 比“无中继”更强
- 但容易把流量集中压到最近的 UAV 上
- 遇到热点中继过载或低能量时，成功率仍明显下降

### Your Method：主动式负载均衡中继

核心思想：

1. **遮挡前瞻**：对即将进入盲区的 UAV 提前预选中继
2. **中继评分**：按多因素打分选择 relay

评分由以下部分构成：

- 中继稳定性（未来是否即将进入盲区）
- 剩余能量
- 空闲容量/当前负载
- 几何邻近性（源 UAV 到 relay 的链路代价）

3. **优先避免热点 relay**：如果当前首选 relay 已接近过载，则切换到次优但更空闲的 relay
4. **盲区零等待切换**：当直连失效时，直接启用预选 relay，无需像 Baseline 2 那样等待检测周期

因此，该方法本质上是：

> **“遮挡预测 + 负载均衡 + 能量感知”的协同中继策略**

## 评估指标

| 指标 | 含义 | 目标 |
|------|------|------|
| **任务成功率** | 所有请求中成功送达的比例 | 越高越好 |
| **业务完成时延** | 成功时延与失败超时统一统计后的平均业务时延 | 越低越好 |
| **盲区救援率** | 处于卫星盲区的请求中，有多少能通过 UAV 中继成功送达 | 越高越好 |
| **平均恢复时间** | UAV 进入盲区后，业务重新恢复可用所需的平均步数 | 越低越好 |

补充统计：

- `overload_events`: 中继热点过载次数
- `relay_usage`: 中继路径被使用的总次数

这些补充指标保存在 `metrics.json` 中，用于后续分析，但不作为本实验的 4 个主展示指标。

## 最终结果

本次实际运行得到的最终结果如下：

| 指标 | Baseline1 | Baseline2 | Your Method |
|------|-----------|-----------|-------------|
| 任务成功率 | 44.0% | 67.7% | **87.4%** |
| 业务完成时延 | 849.30 ms | 754.48 ms | **662.74 ms** |
| 盲区救援率 | 0.0% | 42.3% | **77.5%** |
| 平均恢复时间 | 58.33 steps | 3.80 steps | **2.00 steps** |

### 相对 Baseline1 的提升

- 成功率提升 **43.4 个百分点**
- 平均业务时延下降 **22.0%**
- 盲区救援率提升 **77.5 个百分点**
- 恢复时间从 **58.33 steps** 降到 **2.00 steps**

### 结果解读

1. **无中继方案在盲区中几乎没有恢复能力**
   - 任务成功率只有 44.0%
   - 平均恢复时间高达 58 步以上
   - 这说明单纯依赖卫星直连在遮挡场景下鲁棒性很差

2. **被动中继能补盲，但不够稳定**
   - 成功率提高到 67.7%
   - 盲区救援率达到 42.3%
   - 但仍需等待检测与切换，中断恢复不够快

3. **主动式负载均衡中继效果最优**
   - 盲区救援率达到 77.5%
   - 成功率达到 87.4%
   - 恢复时间仅 2 步，远低于无中继的 58 步

换句话说，这个实验证明了：

> **UAV 中继真正的价值，不只是“能转发”，而是“能在盲区到来之前做好协同准备，并避免所有流量挤向同一个热点中继”。**

## 实验结论

实验三从“遮挡补盲”的角度补齐了实验 1、2 之外的另一类能力验证：

- 实验 1 证明“缓存 + 路由协同”有收益
- 实验 2 证明“动态拓扑下你的方法更稳”
- **实验 3 进一步证明：在卫星接入失效时，UAV 中继能够把大量原本会中断的业务重新接上，而且主动协同中继明显优于被动反应式中继**

因此，这组实验可以形成一条比较完整的论证链：

1. 有缓存协同时更高效
2. 在动态拓扑下更稳定
3. 在接入盲区下还能依赖 UAV 中继维持连续服务
